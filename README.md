# Автотесты сайта ЛМШ «Альтернатива»

UI-автотесты и тестовая документация для [altlmsh.site](https://altlmsh.site), сайта летней многопрофильной школы, который я поддерживаю. Тесты проверяют, что страницы открываются без ошибок, ссылки и картинки рабочие, правила из README сайта соблюдаются, а меню, фильтры и просмотр фото работают на десктопе, на телефоне и с клавиатуры.

Стек: Python, pytest, Playwright, pytest-html, GitHub Actions.

## Результат

**103 проверки: 100 проходят, 3 нашли дефекты.** Дефекты оформлены в [баг-репорты](docs/bug-reports.md):

| ID | Что | Серьёзность |
|---|---|---|
| BUG-001 | На `it.html` при ширине 320 px появляется горизонтальная прокрутка: карточки тем шире экрана | Minor |
| BUG-002 | При неизвестном значении фильтра в адресе (`?year=abc`) не видно, что фильтр включён | Trivial |
| BUG-003 | Фото, которое открывается по нажатию, экранная читалка не объявляет как кнопку | Minor |

Тесты на эти дефекты отмечены `xfail(strict=True)`: прогон остаётся зелёным, но после исправления бага тест упадёт с XPASS и напомнит снять отметку.

## Что проверяется

| Файл | Проверки |
|---|---|
| [`tests/test_pages.py`](tests/test_pages.py) | для **каждой страницы из `sitemap.xml`**: код 200 и нет ошибок в консоли; `lang`, `title`, один `h1`; мета-теги и Open Graph по правилам README; картинки загружаются и имеют `alt`; внутренние ссылки и якоря ведут на существующие страницы; номер версии `style.css?v=` совпадает с главной |
| [`tests/test_navigation.py`](tests/test_navigation.py) | меню одинаковое на всех страницах; страницы меню есть в `sitemap.xml`; `robots.txt`; мобильное меню (открытие, закрытие, `aria-expanded`); нет горизонтальной прокрутки на 320/375/768 px |
| [`tests/test_features.py`](tests/test_features.py) | фильтры «Люди»: по году, по кафедре из адреса, сброс, год без смены, неизвестное значение; ссылки на годы в «Истории»; просмотр фото мышью и с клавиатуры, фокус после закрытия, роль кнопки |

Список страниц тесты берут из `sitemap.xml` проверяемого сайта (`pytest_generate_tests` в [`conftest.py`](tests/conftest.py)). Добавили на сайт страницу — она сразу попадает под все проверки.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m playwright install chromium

pytest -v                                         # против живого сайта
pytest -v --base-url http://localhost:8080        # против локальной копии
pytest -v --headed --slowmo 300 -k mobile         # посмотреть глазами
pytest --html=report.html --self-contained-html   # HTML-отчёт
```

Локальную копию сайта можно поднять так: `python -m http.server 8080` в папке сайта.

## CI

[`.github/workflows/tests.yml`](.github/workflows/tests.yml) запускает тесты на каждый push и каждый день по расписанию против живого сайта. Так поломка после выкладки найдётся, даже если в этот репозиторий никто не коммитил. Прогон можно запустить вручную с другим адресом, например для тестового стенда. HTML-отчёт и скриншоты упавших тестов сохраняются как артефакты.
