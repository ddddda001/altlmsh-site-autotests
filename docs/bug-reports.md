# Баг-репорты

Найдены автотестами при прогоне 17.10.2026 на версии из ветки `main`. Все три исправлены на сайте 18.10.2026: тесты на них прошли с XPASS, отметки `xfail` сняты, и теперь это обычные регрессионные проверки.

## BUG-001. На странице «Информатика» горизонтальная прокрутка при ширине экрана 320 px

| | |
|---|---|
| Серьёзность | Minor |
| Приоритет | Medium |
| Статус | **Исправлен** 18.10.2026 |
| Окружение | Chromium, ширина окна 320 px (iPhone SE первого поколения, узкие Android) |
| Тест | `tests/test_navigation.py::test_no_horizontal_scroll_on_phones[320]` |

**Шаги:**
1. Открыть https://altlmsh.site/it.html в окне шириной 320 px.
2. Пролистать до раздела «О чём бывают пары».

**Ожидаемый результат:** страница помещается по ширине, горизонтальной прокрутки нет.

**Фактический результат:** страница шире окна на 20 px, её можно сдвинуть вбок. Карточки тем выходят за правый край.

**Причина:** карточка `.topic` — элемент grid-сетки `.topics`, и по умолчанию у неё `min-width: auto`. Поэтому карточка не может быть уже своего содержимого, а длинное слово «Программирование» в заголовке вместе с отступами и счётчиком пар не помещается в 320 px. На остальных кафедрах таких длинных слов нет, поэтому баг проявляется только здесь.

**Как исправить:** добавить `min-width: 0` для `.topic` (или `grid-template-columns: minmax(0, 1fr)` для `.topics`), а заголовку разрешить перенос: `overflow-wrap: anywhere`. С `min-width: 0` лишняя ширина пропадает (проверено подстановкой стиля в браузере).

**Как исправлено:** `min-width: 0` у карточки и у её заголовка, а в слове «Программирование» мягкий перенос (`&shy;`), чтобы оно делилось с дефисом в любом браузере.

## BUG-002. При неизвестном значении фильтра в адресе не видно, что фильтр включён

| | |
|---|---|
| Серьёзность | Trivial |
| Приоритет | Low |
| Статус | **Исправлен** 18.10.2026 |
| Тест | `tests/test_features.py::test_people_unknown_filter_value` |

**Шаги:**
1. Открыть https://altlmsh.site/people.html?year=abc (или ссылку с годом, которого нет среди кнопок).

**Ожидаемый результат:** понятно, что действует фильтр по году, и его можно сбросить. Либо неизвестное значение игнорируется и показываются все.

**Фактический результат:** статус «Никого не нашли — попробуй другой год или кафедру», карточек нет, а в ряду «Год» не нажата ни одна кнопка, включая «Все». Пользователь видит пустой список, но не понимает почему.

**Как исправить:** в `people.js` при чтении параметров из адреса оставлять только значения, для которых есть кнопка:
`if (!allYears.map(String).includes(chosen.year)) chosen.year = '';` и так же для кафедры.

**Как исправлено:** выбран первый вариант из ожидаемого результата, чтобы не сломать сценарий «год без смены» (`?year=2020` по-прежнему показывает «Никого не нашли»). Для значения из адреса, которому нет кнопки, в ряду фильтра появляется нажатая кнопка с этим значением, сбросить его можно кнопкой «Все».

## BUG-003. Фото, которое открывается по нажатию, экранная читалка не объявляет как кнопку

| | |
|---|---|
| Серьёзность | Minor (доступность) |
| Приоритет | Low |
| Статус | **Исправлен** 18.10.2026 |
| Тест | `tests/test_features.py::test_photo_has_button_semantics` |

**Шаги:**
1. Открыть `/history.html` с включённой экранной читалкой (NVDA, VoiceOver).
2. Перейти Tab'ом на фото в блоке смены.

**Ожидаемый результат:** читалка сообщает, что элемент можно нажать, например «Фото смены, кнопка».

**Фактический результат:** фото попадает в порядок Tab (`tabIndex = 0`) и открывается по Enter, но объявляется как обычная картинка. Человек без зрения не узнает, что его можно открыть. Пробел, стандартная клавиша для кнопок, фото не открывает.

**Как исправить:** в `photos.js` добавить `photo.setAttribute('role', 'button')` и обрабатывать `event.key === ' '` так же, как Enter.

**Как исправлено:** так и сделано — у фото `role="button"`, открывается по Enter и по пробелу.
